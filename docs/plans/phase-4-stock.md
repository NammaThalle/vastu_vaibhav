# Phase 4 plan: remedy stock, supplier orders and margins

Status: planned, not built. Phase 3 (receipts, bills, WhatsApp) comes first.

## Goal

Know how many bottles of each remedy are in hand and what each one earns, without typing stock numbers in. Stock comes in from supplier orders, which are read from the supplier site automatically every day. Stock goes out when a remedy is added to a bill.

## Facts this plan is built on

- One supplier, Grace Mystics. The site runs on Odoo 19 (hosted by Odoo), with an email or mobile number and password sign-in and no one-time code (checked 27 Nov 2026 from the public pages only).
- Order list: `/my/orders`. Order page: `/my/orders/<id>`, which also lists its delivery orders (`WH/OUT/01261`) with a status such as Shipped. Every page needs sign-in.
- Product links end in the supplier's product number, for example `/shop/virtual-entry-5ml-34` is product 34. This number is the stable key for matching; names can change.
- Supplier names differ from ours: "Virtual Entry 5ml" is our Virtual Door Opener (5ml). Some items are bought for personal use (the pendulum dowsing board) and must never count as stock.
- The supplier sells 5ml and 15ml bottles. Delivery is usually Rs 0.
- Example: WH/OUT/01261, 2 Nov 2026: 4 Virtual Entry 5ml and 4 Toilet Blocker 5ml at Rs 645 each, plus the pendulum at Rs 329. Business cost Rs 5,160.

## Decisions

- **Stock moves on delivery, not on order.** A delivery order is the record that adds stock, and only once it shows Shipped. Until then it shows as "on the way". The sales order number is kept as a reference.
- **Stock is derived, never stored.** The same rule as balances: stock = last count + shipped deliveries since + adjustments since - remedies billed since (voided bill lines ignored).
- **Matching is remembered per supplier product.** The first time a product appears, the user picks the catalog item or "Not for business". After that, every order matches without asking. Nothing is guessed: an unmatched product holds its delivery until it is matched.
- **The supplier password never leaves the server.** It sits in the server's `.env`, is read as a secret, is never logged, and is never returned by the API.
- **Paste stays as a fallback.** The same reader handles text copied from the supplier site, and the review screen doubles as a manual form.
- **Costs are not shown on screens a client might see.** Cost and margin appear on the Catalog screen and in reports, not on the property page or bills.

## Data model

New tables, autogenerated into a new Alembic migration:

| Table | Columns | Notes |
| --- | --- | --- |
| `suppliers` | name, base_url | One row today. |
| `supplier_products` | supplier_id, external_ref, name, size_ml, catalog_item_id, not_for_business | Unique (supplier_id, external_ref). `external_ref` is the product number, or the name when a paste has no links. |
| `deliveries` | supplier_id, delivery_no, order_no, delivery_date, status (on_the_way, received, cancelled), received_on, delivery_charge, source (sync, paste, manual) | Unique (supplier_id, delivery_no). |
| `delivery_lines` | delivery_id, supplier_product_id, catalog_item_id, quantity, unit_cost | `catalog_item_id` is copied from the match when the line is saved, so remapping a product later does not rewrite history. Null for not-for-business lines. |
| `stock_adjustments` | catalog_item_id, kind (count, add, remove), quantity, reason, adjusted_on | A `count` sets the stock to an exact number on a date (opening stock, recounts). `add` and `remove` cover gifts, breakage and samples. |
| `sync_runs` | started_at, finished_at, ok, message, deliveries_added | Shows the last sync and any failure; also prevents two syncs at once. |

Only remedies are stocked. Services are never counted.

## Supplier sync

`app/services/supplier/`:

- `client.py`: signs in and fetches pages with `httpx`.
  1. GET `/web/login`, read the `csrf_token`.
  2. POST `login`, `password`, `csrf_token`. Signed in if the session cookie is set and the response is not the login page again.
  3. GET `/my/orders` and its next pages, collect order links.
  4. GET each order that is new or still has a delivery on the way. Already received orders are skipped.
  5. One request at a time, a short pause between requests, a generic user agent. A normal run is a few page loads.
- `parse.py`: turns an order page, or pasted text, into deliveries and lines: delivery number, date (day first), status, product number, name, quantity, unit price, amount, total. Checks that quantity times price equals each amount and that the lines add up to the total; anything else is an error, not a guess. Treats "Standard delivery" as a delivery charge, not a product.
- `sync.py`: saves new deliveries, updates on-the-way deliveries to received or cancelled, creates `supplier_products` for unseen product numbers, and records a `sync_runs` row. A failure in one order does not stop the others; a sign-in failure stops the run and is reported.

Running it:

- Daily from the host crontab, the same way as backups: `docker compose run --rm api python -m app.cli.supplier_sync`.
- "Sync now" button for the admin: `POST /api/v1/stock/sync`, run in the background, refused if a sync is already running.

Settings in `deploy/.env`: `SUPPLIER_BASE_URL`, `SUPPLIER_LOGIN`, `SUPPLIER_PASSWORD`. Without them the sync is off and only paste works.

## Screens

No new tab. Stock lives on the Catalog screen, since that is where remedies already are.

- **Catalog, remedy rows**: in stock, average cost, margin per bottle. Red when at or below the low stock level (default 3, set in `config/app-settings.json`).
- **Catalog, top**: last sync time and result, Sync now, Paste an order, and "2 products to match" when any are waiting.
- **Match a product**: "Virtual Entry 5ml, supplier no. 34". Choose from the remedies of the same size, or Not for business.
- **Supplier orders**: list of deliveries with status, total and business cost; tap for lines.
- **Count stock**: enter today's count for each remedy; used for the opening stock and later recounts.
- **Home**: "Low stock: Toilet Blocker (5ml), 2 left" and "Supplier sync failed yesterday" when relevant.

## Margins

- Average cost per remedy: total cost of received lines divided by bottles received, delivery charges excluded while they are Rs 0.
- Margin per bottle: list price minus average cost. For a sold line, its own unit price minus average cost.
- Monthly remedy margin on Home is a candidate for Phase 6 reports, not this phase.

## Tests

- Parser tests on saved copies of real pages (order list and one order page) and on the pasted sample, including a copy pasted from a phone.
- Sync tests against those saved pages served through `httpx.MockTransport`: sign-in failure, a new order, an order going from on the way to received, an unmatched product, a page that does not add up.
- Stock tests: count then sales then delivery, voided bill lines, a recount resetting the number.
- No test ever contacts the supplier site.

## Build order

1. Tables and migration, stock and margin calculation, stock count screen.
2. Pasted-order reader, review screen, product matching.
3. Signed-in sync, CLI and Sync now, sync status and failure on Home.
4. Catalog stock columns, low stock on Home, docs.
5. First live run on the server by the user, with the password in `.env`.

## Needed from the user before building

- One order page and the order list page saved from the browser (File, Save Page As), used only as test fixtures.
- One order pasted from the phone.
- The opening stock count, entered in the app once this is built.
- The supplier login added to the server's `.env`. Use a password not used anywhere else.

## Risks

- If the supplier turns on two-step sign-in or a captcha, the sync stops; paste still works.
- An Odoo update can change the page layout. The parser fails loudly instead of guessing, Home shows the failure, and the fix is limited to `parse.py`.
- Odoo's official programming interface would be sturdier than reading pages, but supplier customer accounts usually cannot use it on Odoo's hosted plans. Worth one test once sign-in works; not relied on.
